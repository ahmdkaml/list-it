# Agent Guide: Project Scripts & GitHub Workflows

This document is the authoritative operational playbook for the assistant. Consult this file directly whenever executing build/test tasks or performing GitHub repository workflows.

---

## 1. Request to PowerShell Script Mapping (`scripts/`)

| User Request / Intent | PowerShell Command | Notes |
| :--- | :--- | :--- |
| **Build the application** | `.\scripts\build-app.ps1` | Publishes single-file framework-dependent binary to `publish/ListIt.exe`. Use `-Clean` to clean output first. |
| **Build the installer** | `.\scripts\build-installer.ps1` | Compiles WiX installer package to `dist/ListIt.msi`. Use `-Clean` to clean dist first. |
| **Run the installer** | `.\scripts\run-installer.ps1 -Passive` | Stops running `ListIt.exe` and runs `msiexec.exe /i dist\ListIt.msi /passive`. Omit `-Passive` for interactive UI. |
| **Run the application** | `.\scripts\run-app.ps1` | Launches `publish/ListIt.exe`. Pass `-Build` to force a rebuild before launching. |
| **Run all tests** | `.\scripts\run-tests.ps1` | Executes all xUnit tests across the solution. |
| **Run single test project** | `.\scripts\run-tests.ps1 -Project ListIt.Tests` | Tests only the specified project. |
| **Run single test file/class** | `.\scripts\run-tests.ps1 -Class <ClassName>` | e.g. `.\scripts\run-tests.ps1 -Class BasicFunctionalityTests` |
| **Run single test method** | `.\scripts\run-tests.ps1 -Test <MethodName>` | e.g. `.\scripts\run-tests.ps1 -Test TaskModel_InitializesCorrectly` |
| **List discovered tests** | `.\scripts\run-tests.ps1 -List` | Lists discovered tests without executing them. |
| **Full build pipeline** | `.\scripts\full-build.ps1` | Runs `build-app.ps1` -> `build-installer.ps1` -> `run-installer.ps1`. Use `-SkipRun` to build without running. |
| **Build specific project** | `.\scripts\build-project.ps1 -Project <Name>` | Options: `App`, `Installer`, `Tests`, `All`. |
| **Build solution** | `.\scripts\build-sln.ps1` | Builds `ListIt.slnx` (Release by default). |
| **Clean build artifacts** | `.\scripts\clean.ps1` | Wipes `publish/`, `dist/`, `bin/`, `obj/`, and `install.log`. |

### Versioning Rule for Installer Runs
> **CRITICAL**: Any run or build of the installer (`run-installer.ps1`, `build-installer.ps1`, `full-build.ps1`) **requires bumping the version**.
> WiX's `<MajorUpgrade>` rejects re-installing or downgrading identical versions (`A newer version of [ProductName] is already installed`).
> Always bump the version in both files before building/running the installer:
> 1. `ListIt/ListIt.csproj`: `<Version>X.Y.Z</Version>` and `<FileVersion>X.Y.Z.0</FileVersion>`
> 2. `ListIt.Installer/Package.wxs`: `Version="X.Y.Z"`

## 2. GitHub Operations Playbook

### Credentials Retrieval
GitHub credentials are saved in `$HOME\.git-credentials`.
Extract the personal access token in PowerShell:
```powershell
$credLine = Get-Content "$HOME\.git-credentials" | Where-Object { $_ -match "github\.com" } | Select-Object -First 1
$uri = [System.Uri]$credLine
$token = $uri.UserInfo.Split(":")[1]
$headers = @{
    "Authorization" = "Bearer $token"
    "Accept"        = "application/vnd.github+json"
    "User-Agent"    = "Antigravity-Agent"
    "X-GitHub-Api-Version" = "2022-11-28"
}
```

### Raising a GitHub Issue
> **Rule**: Icons/emojis **must** be used in GitHub issue titles and section headers (🎯 Goal, 🔍 Current State, 💡 Proposed Solution, 📋 Acceptance Criteria), but **never** in technical implementation plans or source code.

```powershell
$body = @{
    title = "🎨 <Issue Title>"
    body  = @"
## 🎯 Goal
<High-level goal>

## 🔍 Current State
<Current state or problem>

## 💡 Proposed Solution
<Proposed design or changes>

## 📋 Acceptance Criteria
- [ ] <Criterion 1>
- [ ] <Criterion 2>
"@
} | ConvertTo-Json

$issue = Invoke-RestMethod -Uri "https://api.github.com/repos/ahmdkaml/list-it/issues" -Method Post -Headers $headers -Body $body -ContentType "application/json; charset=utf-8"
Write-Output "Created Issue #$($issue.number): $($issue.html_url)"
```

### Git Branch, Commit & Push
```powershell
# 1. Create and switch to new branch
git checkout -b feat/issue-<number>-<description>

# 2. Stage changes
git add <files>

# 3. Commit with co-author credit
git commit -m "<Commit message>`n`nCo-authored-by: Antigravity <antigravity@google.com>"

# 4. Push to origin
git push -u origin feat/issue-<number>-<description>
```

### Creating a Pull Request
```powershell
$prBody = @{
    title = "<PR Title>"
    head  = "<branch-name>"
    base  = "main"
    body  = "Closes #<issue_number>`n`n### Summary of Changes`n- <change 1>`n- <change 2>"
} | ConvertTo-Json

$pr = Invoke-RestMethod -Uri "https://api.github.com/repos/ahmdkaml/list-it/pulls" -Method Post -Headers $headers -Body $prBody -ContentType "application/json; charset=utf-8"
Write-Output "Created PR #$($pr.number): $($pr.html_url)"
```

### Merging a Pull Request
```powershell
$mergeBody = @{
    merge_method = "squash"
} | ConvertTo-Json

$merge = Invoke-RestMethod -Uri "https://api.github.com/repos/ahmdkaml/list-it/pulls/$($pr.number)/merge" -Method Put -Headers $headers -Body $mergeBody -ContentType "application/json; charset=utf-8"
Write-Output "Merged PR #$($pr.number): $($merge.message)"
```

### Syncing Local `main`
```powershell
git checkout main
git pull origin main
```
